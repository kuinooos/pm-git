## ② Router 路由测试 — 意图识别

**需要 LLM API 可用**（LongCat API Key 配好）。

### 运行

```bash
cd backend
python -c "

from src.domain.workflows.graph import build_graph

g = build_graph(checkpointer=None)

# 测试1: 闲聊
r1 = g.invoke({'raw_payload': {'user_message': '你好，你会做什么？'}, 'target_country': 'EU', 'approved': False, 'retry_count': 0})

# 测试2: 政策查询
r2 = g.invoke({'raw_payload': {'user_message': 'CBAM对铝制品有什么要求？'}, 'target_country': 'EU', 'approved': False, 'retry_count': 0})
```

### 4.4 保护端点测试

```bash
# 无 Token → 401
curl -X POST http://localhost:8008/api/v1/audit/start \
  -H "Content-Type: application/json" \
  -d '{"bom_data":{"test":"data"}}'
# → 401

# 有 Token → 200 或 500（500 也说明认证通过了，是 LLM 没配好）
TOKEN=$(curl -s -X POST http://localhost:8008/api/v1/auth/token \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | python -c "import sys,json; print(json.load(sys.stdin)['access_token'])")

curl -X POST http://localhost:8008/api/v1/audit/start \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"bom_data":{"product_name":"铝合金型材","hs_code":"7604","weight_kg":60000,"material":"铝","origin_port":"深圳","destination_port":"汉堡","transport_mode":"sea"},"target_country":"EU"}'
# → 200，返回 thread_id + review_data
```

### 5.2 三个场景 + 详细示例

系统通过 **Router Agent** 自动识别用户意图，分流到三个处理路径：

```
用户输入 → Router Agent →  chat ─────────→  LLM 闲聊回复
                         →  policy_query ─→  RAG 政策检索
                         →  carbon_audit ─→  多 Agent 编排工作流
                                              (信息萃取→政策判定→排放计算→风控→审批→报告)
```

---

#### 场景一：🗣️ 闲聊 (chat)

> 纯粹打招呼或询问系统能力，LLM 直接回复，**不触发 Agent 工作流**。

**可复制测试的输入：**

```
你好，你是谁？
```
```
你会做什么？
```
```
介绍一下这个系统有什么用
```
```
你能帮我处理哪些碳关税相关的业务？
```

**预期表现：**
- Router 判定 `chat`
- 返回助手介绍回复
- **不出现** Agent Step 面板
- 响应较快（无工作流编排开销）

---

#### 场景二：📚 政策查询 (policy_query)

> 询问 CBAM/CCA 政策法规条款，走 RAG 向量检索知识库。

**可复制测试的输入：**

```
CBAM 对铝制品有什么要求？
```
```
美国 CCA 碳关税和欧盟 CBAM 有什么区别？
```
```
欧盟碳排放基准值是多少？怎么算的？
```
```
钢铁出口欧盟要交多少碳关税？
```
```
CBAM 过渡期企业有哪些义务？
```

**预期表现：**
- Router 判定 `policy_query`
- 出现 `📚 RAG 政策检索` Step 面板
- 返回相关政策文本片段（标注来源文档）
- 响应时间约 3-10 秒（取决于 LLM + 向量检索）

---

#### 场景三：🔍 碳合规审计 (carbon_audit) ⭐ 核心功能

> 给出具体产品数据，走完整的 **多智能体编排工作流**：

```
Router → 信息萃取 Agent → 政策判定 Agent → 排放计算 Agent
→ 合规风控 Agent → ⏸️ 暂停等待人工审批 → 报告生成 Agent
```

**可复制测试的输入：**

**示例 1 — 铝合金出口欧盟：**
```
我们有 60 吨铝合金型材，HS Code 7604，从深圳海运到德国汉堡，
生产用电 1200 MWh。请帮我做欧盟 CBAM 合规审计。
```

**示例 2 — 钢材出口欧盟：**
```
100 吨钢材，HS Code 7208，从上海港出口到荷兰鹿特丹，
生产用电 800 MWh，天然气 5000 立方米，帮我算 CBAM 碳关税。
```

**示例 3 — 化肥出口美国 (CCA)：**
```
50 吨化肥产品，从天津港海运到美国洛杉矶，帮我做 CCA 合规审计。
```

**示例 4 — 水泥出口欧盟：**
```
我是做水泥出口的，30 吨水泥从广州到法国勒阿弗尔，
用电 600 MWh，运输距离 15000 公里，帮我审计。
```

**预期表现：**
- Router 判定 `carbon_audit`
- 依次出现 5 个 Agent Step 面板，每个面板展示有意义的中间结果：
  1. `🔍 信息萃取 Agent` — 提取产品名、HS Code、重量、港口、材料类型等
  2. `📜 政策判定 Agent (RAG)` — 判定 CBAM/CCA 管控品类、基准值、免费配额
  3. `🧮 排放计算 Agent` — Scope1/2/3 排放量、应纳税排放、预估碳关税
  4. `⚖️ 合规风控 Agent` — 风险等级、合规风险分析
  5. `⏸️ 看板状态: 等待人工审查` — 展示审查摘要
- **出现两个审批按钮**：`✅ 通过审查` / `❌ 驳回`

---

#### 审批操作

| 操作 | 预期 |
|------|------|
| 点击 **✅ 通过审查** | 继续执行 → `📝 报告生成 Agent` → 显示报告 + PDF 下载按钮 |
| 点击 **❌ 驳回** | 工作流终止 → 显示"审计任务已驳回" → 可发起新任务 |

---

#### 路由判断逻辑速查

| 用户输入特征 | 路由结果 | 说明 |
|-------------|---------|------|
| 纯打招呼 / "你会什么" / "介绍一下" | `chat` | 不触发任何 Agent |
| 问政策是什么、条款怎么规定 | `policy_query` | 走 RAG 检索 |
| 给了具体数据（产品 + 重量 + HS Code + 出口国） | `carbon_audit` | 走完整编排 |
| 只提了产品但没给 HS Code / 重量 | 由 LLM 判定 | 建议尽量提供完整信息 |

> **小技巧：** 如果碳审计后想重新发起新任务，输入 **"新任务"** 即可重置会话。

### 5.3 关键验证点

- [ ] 闲聊不触发 Agent 工作流（没有 Step 面板出现）
- [ ] 碳审计时每个 Agent 的 Step 面板都有有意义的内容（非空）
- [ ] 审批按钮正常显示和点击
- [ ] PDF 报告能正常生成并下载
