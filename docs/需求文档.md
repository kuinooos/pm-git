# 全球碳关税（CBAM/CCA）合规审计多智能体系统 - 需求文档

## 项目背景

全球碳关税（CBAM/CCA）合规审计多智能体系统（Global Carbon Tariff Compliance Audit Multi-Agent System）。

在实际跨境贸易中，碳审计极其复杂。例如，一件出口的铝制配件，需要根据海关编码（HS Code）匹配其是否在欧盟 CBAM 或美国 CCA 的征税范围内，接着需要基于运输路径计算范围三（Scope 3）碳排，再结合采购的原铝级别（范围一、二）进行核算，最后对照复杂的法规细则进行差异性合规评估。在这个过程中，单一 Agent 很容易因为上下文过长、推理链条过深而产生幻觉。

因此，引入 **LangGraph**（多体协同与有状态图逻辑）、**LangChain RAG**（精准政策检索）、**FastAPI**（高并发异步后端）以及 **Human-in-the-Loop**（人工确认机制）是应对此类复杂、严谨商业场景的高效技术组合。

---

## 一、系统业务需求分析

系统主要针对出海制造企业、跨境物流企业和跨国供应链咨询机构，提供以下核心功能：

1. **多源异构数据接入（FastAPI 承接）**：支持企业 ERP 系统的 BOM（物料清单）、TMS（运输管理系统）的物流轨迹、海运提单（PDF/Excel）的数据导入。
2. **智能 HS Code 与政策判定（RAG + Tool Agent）**：通过 RAG 检索最新的欧盟 CBAM / 美国 CCA 法规数据库，智能判定出口货物对应的海关编码（HS Code）是否属于碳关税管控品类、计算方法学以及起征基准值。
3. **分阶段多体协同审计（LangGraph 工作流）**：
   - **信息萃取 Agent**：清洗并验证输入数据的完整性。
   - **政策判定 Agent**：执行 RAG 政策匹配。
   - **物理计算 Agent**：调用本地碳排放因子数据库及地理计算 API 计算排放。
   - **合规风控 Agent**：对比目标国减排基准值，识别超标风险并给出整改建议。
4. **人工审查确认机制（Human-in-the-Loop）**：鉴于审计的严谨性，在生成最终报告前，LangGraph 在特定节点暂停并挂起，等待人工合规官审查计算因子和判定结果，确认或修改后方可继续流转。
5. **合规审计报告自动化渲染（PDF/Markdown）**：生成符合 ISO 14064 或国别 CBAM 申报标准的审计报告。

### 架构核心设计思想

- **API 网关层**：FastAPI 充当引擎舱，负责会话鉴权、限流以及与 ERP 等外部系统的 BOM、TMS 数据对接。
- **多智能体工作流引擎**：基于 LangGraph 构建有状态图（StateGraph），而非简单链式调用。这允许循环（Loop）和条件跳转（Conditional Edge），尤其是在"人工审查"环节可以实现暂停/恢复逻辑。
- **多格式渲染**：直接从 State 中的 Markdown 草稿，通过 FPDF2 或 WeasyPrint 转换为 PDF，实现报告自动化。

## 三、核心功能模块实现逻辑

### 1. 知识检索引擎（基于 LangChain RAG）

构建专有的"碳合规知识库"：

- **数据源**：欧盟官方 CBAM 条例、美国 CCA 草案文件、各国 HS Code 对照表、ISO 14064 核查标准。
- **技术栈**：使用 LangChain 的 StructuredPDFParser 解析非结构化 PDF 政策文件，利用 Chroma 或 Milvus 作为向量数据库与 HuggingFaceEmbeddings。
- **混合检索（Hybrid Search）与 Rerank（重排）**：引入先由 BM25 进行海运编号/商品品类关键词检索，再与向量检索融合，最后通过 BGE-Reranker 对检索出来的 Top-10 政策条例进行相关性精筛，确保 Agent 获得的基准数据准确。

### 2. 多智能体协同设计（基于 LangGraph）

利用 LangGraph 建立带有状态循环（Cycle）和人工介入（HITL）的强控制流。

#### 定义状态（State）

`python
from typing import TypedDict, List, Dict, Any

class AuditState(TypedDict):
    raw_payload: Dict[str, Any]     # 原始报关或物料数据
    clean_data: Dict[str, Any]       # 清洗后的标准结构
    hs_code: str                     # 判定得到的 HS Code
    policy_info: str                 # RAG 匹配出的税率与准则
    emissions_result: Dict[str, Any] # 物理计算结果
    compliance_risk: str             # 合规风险分析文本
    approved: bool                   # 人工审核标志
    audit_report_md: str             # 终版报告草案
`

#### 状态图节点设计

- **clean_data_node**：利用 LLM 结构化提取输入数据（如自动提取提单 PDF 或物料 JSON 中的货物类型、重量、源头港、目的港）。
- **rag_policy_node**：将品类、HS Code、目的国传入 RAG 检索器，查询对应的碳关税政策及免费排放额度比例。
- **calculate_emissions_node**：根据提取的路径、重量，调用物理碳排计算器计算 Scope 3 物流碳排，以及根据材料消耗计算 Scope 1 和 Scope 2 碳排。
- **compliance_audit_node**：对比计算值与政策基准值，生成风险分析报告。
- **human_review_gate**：关键分叉路口。如果 state["approved"] 为 False，LangGraph 会在此挂起，将当前状态返回给 FastAPI。
- **generate_report_node**：整合所有审计步骤及人工反馈，撰写正式的合规报告。

### 3. 后端服务层（基于 FastAPI）

#### 会话与持久化管理

使用 LangGraph 的 SqliteSaver 或 PostgresSaver 进行会话状态存盘。这让有状态的 Agent 对话不仅可以随时中断挂起（等待人工审批），还能在服务器重启后无缝恢复执行。

#### 异步 API 设计

| API 端点 | 方法 | 说明 |
|---|---|---|
| /api/v1/audit/start | POST | 接收用户提交的数据，初始化 LangGraph 工作流并运行到人工审计节点前，返回 thread_id |
| /api/v1/audit/status/{thread_id} | GET | 获取当前 Agent 运行的状态树、当前所处节点及中间结果 |
| /api/v1/audit/approve | POST | 接收人工审计确认或修正后的参数，将 approved 设为 True，唤醒挂起的工作流，使其继续运行直至生成最终报告 |
| /api/v1/rag/upload | POST | 提供管理员上传最新政策 PDF 的接口，在后台异步完成向量化更新 |
