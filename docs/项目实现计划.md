## 二、技术选型确认

### 2.1 核心技术栈

| 层级 | 技术 | 版本建议 | 用途 |
|------|------|----------|------|
| **LLM 接口** | LongCat-2.0 (OpenAI 兼容) | - | 主力推理模型 |
| **工作流引擎** | LangGraph | ≥0.2.x | 多智能体状态图编排 |
| **RAG 框架** | LangChain | ≥0.3.x | 文档加载、切分、检索 |
| **向量数据库** | Milvus Lite | ≥2.4.x | 政策文档向量存储（轻量级，本地运行） |
| **Embedding** | HuggingFaceEmbeddings (BGE-M3) | - | 中英双语政策文档向量化 |
| **Reranker** | BGE-Reranker-v2-m3 | - | 检索结果重排序 |
| **后端框架** | FastAPI | ≥0.110.x | 异步 REST API |
| **前端交互** | Chainlit | ≥2.11.x | 用户交互与工作流可视化 |
| **状态持久化** | LangGraph SqliteSaver | - | 工作流断点恢复 |
| **报告渲染** | WeasyPrint / fpdf2 | - | Markdown → PDF |
| **链路追踪** | LangSmith (可选) | - | Agent 执行可观测性 |

### 2.2 关键决策说明

1. **向量数据库选择 Milvus Lite**：项目工作区已有 `lcel-rag-milvus/milvus_lite.db`，说明已有 Milvus Lite 使用经验，且无需额外部署服务。
2. **LLM 继续使用 LongCat-2.0**：复用现有 API Key 和接口配置，保持一致性。
3. **Chainlit 作为前端**：保留现有 Chainlit 框架，在其上扩展工作流可视化和审批交互能力。

#### AuditState 定义

```python
# src/workflows/state.py
from typing import TypedDict, List, Dict, Any, Optional

class AuditState(TypedDict):
    # 输入
    raw_payload: Dict[str, Any]           # 原始报关或物料数据 (BOM/TMS/提单)

    # 信息萃取 Agent 产出
    clean_data: Dict[str, Any]            # 清洗后的标准结构 (货物类型、重量、源头港、目的港等)
    hs_code: str                          # 判定得到的 HS Code
    target_country: str                   # 目标出口国 (EU/US)

    # 政策判定 Agent 产出
    policy_info: str                      # RAG 匹配出的税率与准则
    cbam_category: Optional[str]          # CBAM 管控品类 (aluminum/steel/cement/...)
    free_allowance_rate: Optional[float]  # 免费排放额度比例
    benchmark_value: Optional[float]      # 起征基准值

    # 物理计算 Agent 产出
    emissions_result: Dict[str, Any]      # Scope 1/2/3 分项计算结果
    total_emissions: float                # 总碳排放量 (tCO2)

    # 合规风控 Agent 产出
    compliance_risk: str                  # 合规风险分析文本
    risk_level: str                       # 风险等级 (low/medium/high)
    rectification_advice: str             # 整改建议

    # 人工审查
    approved: bool                        # 人工审核标志 (False=待审核, True=已通过)
    reviewer_feedback: Optional[str]      # 人工修改备注
    pending_review: bool                  # 是否正在挂起等待审核

    # 报告
    audit_report_md: str                  # 终版报告 Markdown 草案
    audit_report_pdf: Optional[str]       # PDF 文件路径
```

## 六、技术风险与应对策略

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| LongCat-2.0 对 LangChain 兼容性问题 | Agent 节点 LLM 调用失败 | 通过 `ChatOpenAI` 兼容接口接入，已有 `langgraph_demo.py` 验证可行 |
| Milvus Lite 本地性能瓶颈 | RAG 检索延迟高 | 先用小规模文档验证，必要时切换至 Milvus Standalone |
| BGE-M3/Reranker 模型下载慢 | 环境搭建阻塞 | 提前下载模型缓存到本地，或使用 HuggingFace 镜像站 |
| LangGraph HITL 与 Chainlit 集成复杂 | 前端审批交互难以实现 | 利用 LangGraph `interrupt` 机制 + Chainlit `cl.Action` 按钮组件 |
| WeasyPrint 在 Windows 上的依赖问题 | PDF 渲染失败 | 备选 `fpdf2` 方案，或使用 `markdown-pdf` 轻量方案 |

## 七、验收标准

### 7.1 功能验收

- [ ] 用户可通过 Chainlit 界面输入 BOM/TMS 数据发起碳审计任务
- [ ] 系统自动执行 5 个 Agent 节点，全过程可通过 `cl.Step` 可视化展示
- [ ] RAG 检索能从政策 PDF 中精准召回相关条款（准确率 > 80%）
- [ ] 碳排放计算覆盖 Scope 1/2/3，结果与碳因子数据库一致
- [ ] 工作流在 `human_review_gate` 节点正确挂起，等待人工确认
- [ ] 人工确认后工作流恢复执行，生成最终审计报告
- [ ] 报告可导出为 PDF 格式，符合 ISO 14064 / CBAM 申报框架
- [ ] FastAPI 端点可独立调用，与 Chainlit 前端功能等价
- [ ] 状态持久化生效：服务器重启后可恢复未完成的审计任务

### 7.2 技术验收

- [ ] 代码结构遵循需求文档中的目录设计
- [ ] 所有模块有类型注解和 docstring
- [ ] 核心模块有单元测试覆盖
- [ ] `requirements.txt` 可一键安装所有依赖
- [ ] README 包含启动说明和架构图
